## 1. 必交文件终稿（逐文件验收要点与内容大纲）

### 1.1 `README.md`（仓库根，覆盖作业 README 前先把作业原文挪到 `docs/TASK.md`）

- **跑通步骤**（≤3 步）：`make setup` → `make rebuild` → `make run`；附 Windows/POSIX 直接命令表（P0 已备）。
- **重建命令**：`python -m kbqa.rebuild` 的完整说明（输入 data/+knowledge_base/，输出 var/，耗时、产物清单）。
- **架构图**：五层图（手画拍照也行）——L1 前端 / L2 契约层 / L3 编排 / L4 工具与检索 / L5 SQLite。
- **选型理由**：保壳换芯、规则主干+LLM 语义层、jieba+BM25∥MiniLM RRF、SQLite 单文件、Vue3 dist 入库——每条两三句"为什么"。
- **口径与歧义取舍**（评分明写要看）：
  - 退款计入净营业额、空金额剔除不回填、客单价 HALF_UP、闭区间（KB-001 v3 依据）；
  - amount=0 行保留标注、两不沾（当前快照实测 0 行）；
  - `'2026-13-45'` 日历非法按规则 1 剔除（datetime.date 构造校验）；
  - 商品现行售价以调价通知为准、建档价只作背景（KB-001 §5.3）；
  - 通知/政策类 > 总表/参考类（KB-062 vs KB-042）；
  - 思考模式**开启**的理由（契约要求写明）：规划更稳 + 评委可观察 reasoning；代价是更慢更贵，max_tokens 显式 4096 防思考吃光额度。
- 向量模型：名称 + 首次下载 ~470MB + 不可用自动降级说明（契约 7.6）。

- 终版：live（DeepSeek 或开发所用模型）跑公开题库的完整输出；无 Key 则降级模式并写明。

### 1.4 `LLM_SETUP.md`

严格按契约 §7.4 八节，每节实际内容（禁"见代码"）：① 厂商/模型/协议/SDK 版本；② 三个环境变量 + TODAY/VAR_DIR 等全量配置表（名字/默认值/读取位置）；③ 切换步骤：改三个环境变量 → 重启即可，**不需要 rebuild**（模型与索引无关）；④ 可观察：`eval/llm_gateway.py proxy` 命令 + trace 里 prompt 查看方法 + 脱敏样例；⑤ 无 Key：服务正常启动、四接口行为、chat 走 mock 规则管线；⑥ 依赖：jieba/sentence-transformers/torch 体积与首次启动耗时；⑦ preflight 全过输出原文；⑧ 已知限制（写出来不扣分：如 mock 模式 why 类问题措辞模板化、向量模型首次下载慢）。

## 3. 现场调试环节准备（30 分）

- **定位方法论固化**（README/DEBUG_LOG 里能讲出来）：先复现（重放问题）→ 看 trace（检索分数/过滤原因/工具结果/完整 prompt）→ 形成假设 → 最小实验（/api/retrieve 单独验证）→ 修复 → 红测试 → 回归（regression.py 全量）——评委看的就是"先复现还是先猜"。
- 自挑 2 道当前答错的题走完整流程并计时；把过程写成 DEBUG_LOG 附录风格的演练笔记。
- 模拟"现场加文档"：variant_check 的第 2 步即预演——新文档进 KB → rebuild → 多久能答上（答案：rebuild 一条命令 + 一次检索，分钟级）。
